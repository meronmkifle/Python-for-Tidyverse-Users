From the original session

Sofia Gil-Clavel designed R for Social Scientists for PhD students through to professors, including qualitative researchers who have never used R and quantitative researchers moving out of SPSS or Stata. Each session is three hours, mixes short explanations with hands-on exercises, and assumes the previous sessions.

The sessions fall into five blocks: data handling (1 to 2), exploratory analysis (3 to 4), machine learning (5 to 6), text analysis (7 to 9) and code optimisation (10 to 11), plus an extra session on building an R package. This edition keeps that order and adds three things to every session: a Python translation, a knowledge check, and an applied lab on synthetic health and social policy data.

Why this matters in real work

Most errors in applied work happen before any model is fitted: the wrong population, an unclear time window, or a table whose grain (one row per what?) was never checked. Every applied lab in this edition starts from those questions, and every number in it can be traced back to the embedded synthetic tables.

Common trap

Treating R and Python as interchangeable syntax. They agree on most results, but defaults differ: missing values, regularisation in logistic regression, tf-idf formulas, random number streams. This edition flags each difference where it changes a number.

Knowledge check

A practice code is stored as 000412. What happens if you read it with default type guessing?

From the original session

The session opens with the difference between application software (click, click, click) and a programming language, then tours the four RStudio panes. Students then meet R's primitive data types (numeric, integer, character, logical) with their operators, combine them into vectors with c(), and see that a data frame is a set of equal-length vectors joined side by side.

Exercises use CredHist.csv, a 500-row credit history table with age, sex, history, monthly salary and employment status. Students open it with read.csv(), inspect it with str(), head() and summary(), index rows and columns with [ , ] and $, and save it again with write.csv(); the foreign package covers SPSS and Stata files.

Why this matters in real work

Type decisions made at import travel through the whole pipeline. A code read as a number will not match the same code held as text in another system, so joins quietly return no matches and nothing raises an error.

Common trap

R indexes from 1 and includes both ends (x[2:3]); Python indexes from 0 and excludes the end (x[1:3]). Both return the 2nd and 3rd elements.

R and Python side by side

Types and vectors

R
x <- c(10, 20, 30)
class(x)            # "numeric"
x[1]                # 10 (1-based)
x[2:3]              # 20 30 (inclusive)
x * 2               # vectorised: 20 40 60
is.na(c(1, NA, 3))  # FALSE TRUE FALSE
Python
import numpy as np
x = np.array([10, 20, 30])
x.dtype             # int64
x[0]                # 10 (0-based)
x[1:3]              # [20 30] (end excluded)
x * 2               # vectorised: [20 40 60]
np.isnan([1, np.nan, 3])

A plain Python list is not vectorised: [10, 20, 30] * 2 repeats the list. Use numpy arrays or pandas Series for arithmetic.

Chapter 2 · Tidyverse

Packages, the dplyr verbs, the pipe and grouped summaries.

Original material 02_Session_Tidyverse · Session2_Tidyverse_SGC.pdf (54 slides) · CredHist.csv

Learning objectives

  • Install and load packages, and call functions from a named package with pkg::fun().
  • Explain the tidy data logic: one variable per column, one observation per row.
  • Chain filter, select, mutate, summarise, arrange and group_by with the pipe.
  • Translate each verb into pandas without changing the result.
Knowledge check

mean(age) in R returns NA when one age is missing. What does pandas df['age'].mean() return?

From the original session

Session 2 recaps data types, then introduces packages: what they are, how to install and load them, and how many exist on CRAN. The core of the session is dplyr on the CredHist data: mutate() to create or modify columns, select() to keep or drop columns, filter() to keep rows, summarise() to reduce groups, and arrange() to order rows.

The pipe then chains these verbs into readable pipelines, and group_by() turns a summary into a per-group summary. The session closes with tibbles and with finding help for an unfamiliar function, which is the habit that carries students through the rest of the course.

Why this matters in real work

A grouped summary changes the grain of the data from people to groups. Name that change in code (.groups = "drop", as_index=False) so the next step does not assume it still has one row per person.

Common trap

summarise() with several grouping variables keeps the outer groups by default, so a later mutate() computes within groups you may have forgotten about. pandas groupby() turns group keys into the index unless you pass as_index=False.

R and Python side by side

The five verbs on CredHist

R
library(dplyr)
credhist |>
  filter(AGE >= 30) |>
  mutate(salary_k = SALARY_M / 1000) |>
  select(SEX, HISTORY, salary_k) |>
  group_by(SEX, HISTORY) |>
  summarise(n = n(), mean_salary_k = mean(salary_k), .groups = "drop") |>
  arrange(desc(mean_salary_k))
Python
(credhist
 .loc[lambda d: d["AGE"] >= 30]
 .assign(salary_k=lambda d: d["SALARY_M"] / 1000)
 [["SEX", "HISTORY", "salary_k"]]
 .groupby(["SEX", "HISTORY"], as_index=False)
 .agg(n=("salary_k", "size"), mean_salary_k=("salary_k", "mean"))
 .sort_values("mean_salary_k", ascending=False))

Method chaining in brackets is the pandas equivalent of the pipe. lambda d: refers to the data frame at that point in the chain, like the implicit data argument in dplyr.

Conditional recoding

R
credhist |>
  mutate(age_group = case_when(
    AGE < 30 ~ "under 30",
    AGE < 50 ~ "30 to 49",
    .default = "50 and over")) |>
  count(age_group)
Python
conds = [credhist["AGE"] < 30, credhist["AGE"] < 50]
(credhist
 .assign(age_group=np.select(conds, ["under 30", "30 to 49"], default="50 and over"))

Session 4 · Exploratory analysis

Chapter 4 · Unsupervised learning

Principal components and k-means clustering.

Original material 04_Session_UnsupervisedLearning · Session4_Unsupervised_SGC.pdf (51 slides) · two scripts (PCA, k-means) on ISLR2 Bikeshare

Learning objectives

  • Explain the difference between supervised and unsupervised learning.
  • Standardise variables and run PCA; interpret loadings, scores and variance explained.
  • Cluster with k-means, using several random starts, and interpret clusters against known labels.
Knowledge check

Why standardise before PCA?

From the original session

Session 4 introduces statistical learning following ISLR: why we learn from data, supervised versus unsupervised learning, and the two unsupervised tools used in the course. On the ISLR2 Bikeshare data, students drop categorical variables, inspect correlations with corrplot, standardise the variables, and run prcomp(scale = TRUE).

They read the loadings (rotation), scores (x) and the proportion of variance explained, draw a biplot, and correlate components with the original variables. Then kmeans() with several random starts (nstart) clusters the first principal components, the clusters are plotted in 2D and 3D, and a custom function compares within-cluster correlation structures.

Why this matters in real work

In area-level work, PCA turns several correlated access indicators into one or two interpretable dimensions, and clustering suggests area typologies. Both are descriptive: they summarise the data you have and do not show that the typology is real or stable.

Common trap

The sign of a principal component is arbitrary, so R and Python can return PC1 with opposite signs. prcomp scales by the n-1 standard deviation and StandardScaler by the n version. Loadings and variance explained still agree, but scores differ by a constant factor.

R and Python side by side

PCA and k-means

R
pr.out <- prcomp(X, scale. = TRUE)
pr.out$rotation            # loadings
head(pr.out$x)             # scores
pve <- pr.out$sdev^2 / sum(pr.out$sdev^2)
biplot(pr.out, scale = 0)

set.seed(1)
km.out <- kmeans(pr.out$x[, 1:3], centers = 4, nstart = 100)
table(km.out$cluster)
Python
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA
from sklearn.cluster import KMeans
Z = StandardScaler().fit_transform(X)
pca = PCA().fit(Z)
pca.components_.T          # loadings
scores = pca.transform(Z)  # scores
pve = pca.explained_variance_ratio_

km = KMeans(n_clusters=4, n_init=100, random_state=1).fit(scores[:, :3])
np.bincount(km.labels_)

Cluster labels are arbitrary too: cluster 1 in R may be cluster 3 in Python even when the grouping is identical. Compare cross-tabulations, not label numbers.

Session 5 · Machine learning

Chapter 5 · Statistics

Linear models, assumptions, intervals, interactions, ANOVA and prediction.

Original material 05_Session_Statistics · Session5_Statistics_SGC.pdf (41 slides) · Session5_Statistics_SGC.R (ChickWeight, Titanic)

Learning objectives

  • Write an analysis as a model formula and fit it with lm() or glm().
  • Detect influential outliers and check linear model assumptions.
  • Report coefficients with confidence intervals; add and test interaction terms.
  • Compare nested models with ANOVA and generate predictions with intervals.
Knowledge check

In the lab, the programme coefficient changes when deprivation and disability are added. What does that suggest?

From the original session

Session 5 places statistical modelling in the data science pipeline and teaches students to translate a research question into formula notation (y ~ x1 + x2). On the built-in ChickWeight data they plot weight against time by diet, fit lm(weight ~ Time), find and remove two outlying chicks, and check assumptions with plot(model).

They read coefficients, standard errors and p-values with summary(), get intervals with confint(), add diet as a main effect and then as an interaction (Time * Diet), compare the nested models with anova(), and predict beyond the observed range with predict(..., interval = "prediction"). The homework turns the Titanic table into a tibble and models survival with glm().

Why this matters in real work

Evaluation reports often show the raw difference between participants and non-participants. Selection into a programme is rarely random, so report the adjusted estimate with its interval, state what was adjusted for, and say what could still bias it.

Common trap

statsmodels' formula interface (smf.ols) matches R's lm() exactly, including treatment contrasts with the first level as reference. scikit-learn's LinearRegression gives no standard errors, and its regularised variants change the coefficients.

R and Python side by side

Linear model, intervals, interaction, ANOVA

R

summary(m1)
confint(m1)
m2 <- lm(SALARY_M ~ AGE * SEX, data = credhist)

Python
import statsmodels.formula.api as smf
import statsmodels.api as sm
m1 = smf.ols("SALARY_M ~ AGE + SEX", data=credhist).fit()
print(m1.summary())
m1.conf_int()
m2 = smf.ols("SALARY_M ~ AGE * SEX", data=credhist).fit()
sm.stats.anova_lm(m1, m2)
new = pd.DataFrame({"AGE": [40], "SEX": ["female"]})

Chapter 6 · Supervised learning

Classification with logistic regression and LDA, honest accuracy, resampling.

Original material 06_Session_SupervisedLearning · two slide decks (43 and 52 slides) · Session6_SupervisedLearning_SGC.R (ISLR2 OJ)

Learning objectives

  • Decide when a problem is regression or classification, and prediction or inference.
  • Train logistic regression and LDA classifiers and read a confusion matrix.
  • Evaluate on held-out data and with k-fold cross-validation.
  • Compare accuracy with the accuracy of always predicting the majority class.
Knowledge check

scikit-learn's LogisticRegression() with default settings gives different coefficients from R's glm(). Why?

From the original session

Session 6 recaps k-means, then sets up supervised learning: notation, regression versus classification, and prediction versus inference. On the ISLR2 OJ data students predict whether a customer buys Citrus Hill or Minute Maid, after removing predictors that are exact functions of others.

They fit glm(..., family = binomial), compute a predicted probability by hand from the coefficients, convert probabilities to classes at 0.5, and build a confusion matrix. They repeat this with MASS::lda(), then split the data 70/30 with a seed, write an Accuracy() function, and write their own k-fold CrossValidation() loop to compare the variability of both models with boxplots.

Why this matters in real work

A classifier that is 70% accurate on an outcome with 70% prevalence has learned nothing. Always report the majority-class baseline, and for rare outcomes prefer sensitivity, precision and calibration to raw accuracy.

Common trap

Fitting preprocessing (scaling, imputation, feature selection) on the full data before splitting leaks test information into training. In R use recipes; in Python put the steps in a Pipeline so they are fitted on training folds only.

import time, requests
def get_postcode(pc, tries=3):
    for attempt in range(tries):

Question: Why does the washout use any respiratory admission before baseline, back to 2019?

Show answer

Without it, people already admitted for respiratory disease would count as new events, mixing prevalent and incident cases. The length of look-back available limits how well this works, so state it.

Question: Why does follow-up stop at the first event?

Show answer

The estimand is the rate of a first admission. After the first event a person is no longer at risk of a first event, so their later time does not belong in the denominator.

Question: The interval for the rate ratio is wide. What would narrow it?

Show answer

More events: a larger cohort, longer follow-up, or a broader outcome. With 600 synthetic people, the interval is the honest answer.

Question: What is still missing for a publishable estimate?

Show answer

A validated code list, age and sex standardisation or adjustment, checks on linkage completeness, and the data owner's disclosure rules applied to every published cell.
